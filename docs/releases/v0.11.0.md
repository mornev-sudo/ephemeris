## Ephemeris 0.11.0

A security release, from a review against OWASP's guidance (ASVS 5.0,
Secure by Design, the DevSecOps guideline, the testing guide and cheat
sheets). The router no longer updates itself, passwords are hashed with
yescrypt, SSH can be keys only, network text can't forge log lines, and
the packet path is fuzzed. Releases come with an SBOM and build
provenance, and CI scans the portal on every build.

### Security

**No automatic updates or reboots.** Debian's own `systemd-sysupdate`
timers and services are masked in the image, so a router only updates
when you click Install update or run it yourself, and only reboots when
you say so. CI checks that they stay masked on the booted image. (Before,
the stock timer could download and install a new release on its own.)

**Passwords**
- Hashed with **yescrypt** instead of SHA-512 crypt. Existing passwords
  keep working: the hash is upgraded at the next successful login (web or
  API), and nobody is logged out.
- A new password is refused if it's easy to guess: repeats, runs, keyboard
  walks, or a common word with digits or symbols added. This only applies
  when a password is set; existing passwords aren't checked.

**SSH with keys only**: `[ssh] password_login = false`.
- Applied straight away: ephemerisd writes the setting where sshd reads it
  (`/run/ephemeris-ssh/`) and reloads sshd. Rolling back the commit turns
  passwords back on.
- Refused while no key is installed for root, so you can't lock yourself
  out. The console always takes the password.
- The default is unchanged (passwords allowed).
- Guide: [chapter 19](https://github.com/mornev-sudo/ephemeris/blob/v0.11.0/docs/learn/19-router-access.md#keys-only-for-ssh).

**Logs can't be forged from the network.** Text that arrives in packets
(DHCP host names, the PPPoE concentrator and service names, PAP/CHAP
refusal messages) is cleaned where it's read: control characters escaped,
at most 64 characters. The log writer escapes every line as well, so one
record is always one line.

**Portal headers**: `Cross-Origin-Opener-Policy`,
`Cross-Origin-Resource-Policy` and `Permissions-Policy` on every response.

**Hostile packets**
- Every `cargo test` sends hundreds of thousands of malformed and random
  frames through a router with every feature on (VLANs, PPPoE, NAT,
  SD-WAN, router access), and random input through every parser. None may
  panic or send outside its buffer.
- `fuzz/` has cargo-fuzz targets for the pipeline and the parsers, and CI
  runs each for two minutes on every build.

### Supply chain
- **SBOM** with every release: the image's package list
  (`*.manifest`) and the Rust dependencies in CycloneDX (`*.cdx.json`),
  both listed in the signed `SHA256SUMS`.
- **Build provenance**: images built from `main` are attested with
  GitHub's build provenance (SLSA, signed through Sigstore). Check a
  download with
  `gh attestation verify <file> --repo mornev-sudo/ephemeris`.
- Release signing keys are only available to builds of `main`. Other builds
  sign with throwaway keys, so their boot test still checks Secure Boot and
  signed updates.
- `cargo-deny` in CI: known vulnerabilities (RustSec), licences, crates
  only from crates.io. Dependabot proposes Cargo and Actions updates after
  a waiting period.
- Every GitHub Action is pinned to a commit.

### Testing
- The end-to-end test on the real image also runs an **OWASP ZAP**
  baseline scan and a **testssl.sh** scan of the portal, and fails on
  anything high risk. (The self-signed certificate's own findings, such as
  no trust chain, are expected.) Their reports are kept with the test
  logs.
- New end-to-end checks: updates stay masked, the password hash is
  upgraded at login and SSH still takes the password afterwards, SSH keys
  only (and rolling it back).

### When upgrading
- **Routers on 0.10.2 or earlier can still update themselves** until they
  run 0.11.0, because their automatic update timer is still on. If you
  don't want one to install 0.11.0 on its own schedule, install it yourself
  now (Install update in the portal). After that, updates only happen when
  you start them.
- **Password hash:** the admin password is rehashed with yescrypt at the
  next login. Nothing to do, and falling back to 0.10.2 is still safe:
  it checks passwords with the system's crypt, which reads yescrypt too.
- **New passwords** must pass the guessability check.
- **`/run/ephemeris-ssh/`** is now included by sshd's configuration and
  written by ephemerisd. Don't put your own files there.
